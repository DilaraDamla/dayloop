## Review findings

Reviewed the five itineraries above directly (not assumed) after the `t()` fix below was applied and the file regenerated.

### Defect found and fixed
**`t()`'s variable substitution silently corrupted any value containing a literal "$".** Every cost estimate outside Turkey showed a single "$" regardless of the real budget level (1, 2, *or* 3) — confirmed directly: `estimateDailyCost(stops, 2, ...)` produced `cost.budgetLevel === 2`, yet the rendered text read "$ per person" instead of "$$". Root cause: `String.prototype.replace(pattern, replacementString)` treats `$$` in the replacement *string* as an escape for a single literal `$` — a pre-existing, general bug in the shared `t(key, vars)` i18n helper (used everywhere in the app), never before exposed because Sprint 6's cost estimate was the first feature to ever pass a `$`-containing value through it. Fixed by switching `t()` to a function replacer (`str.replace(pattern, () => v)`), which isn't subject to that special-pattern interpretation — a one-line, targeted fix with no effect on any template that doesn't contain `$`. Regression tests added (`t() correctly substitutes a value containing literal "$" characters...`, `cost estimate produces the correct $/$$/$$$ tier for each real budget level...`). All pre-existing tests re-run clean afterward.

### Weak stops
- None rise to "clearly wrong for the vibe" — no bank/office/school/hospital/wedding-hall-style category ever appears, and this is true **by construction**: `CATEGORY_TAGS` (what `fetchPOIs` even queries for) never included those categories in any sprint, so the sprint's own named concern was already structurally impossible before Sprint 6, not something this sprint had to newly guard against.
- The weakest *individual* stop is the plain **bar** closing out the Adventure evening — technically correct (adventurous's own evening core) but the least "unforgettable" pick compared to the discovery categories now available; it won because `bar_capital_0` was simply closer than `escape_room`/`theatre` in this fixture, not because of any logic error.

### Repeated categories
- **Coffee and food slots are nearly identical across all five vibes** — `bakery_capital_0` wins the coffee slot in *all five* itineraries, and a `restaurant_capital_*` wins food in all five. This is real, directly observed evidence, not a hypothesis. Root cause: `coffee`/`food` core tiers barely differ across vibes (`['cafe','bakery']` and `['restaurant']`/`['restaurant','cafe']` almost everywhere), so with this fixture's distances, the same nearest instance wins regardless of vibe-specific score nudges. **Not fixed this sprint** — meaningfully differentiating coffee/food preference *per vibe* is a real content decision (e.g., should romantic prefer a patisserie-style bakery over adventurous preferring a quick grab-and-go one?), not a small, evidence-driven patch, and retuning it off the strength of one fixture's coincidental tie is exactly what "do not broadly retune based on one fixture" warns against. Documented as a limitation, not silently left unmentioned.

### Generic explanations
- The "close to your previous stop, keeping the route compact" reason fires for 3 of 4 stops in several itineraries. On inspection this is **factually accurate** in this dense fixture (every one of those legs really is under 0.6km) — it's not a wrong or generic-*sounding* explanation being misapplied, it's the honest, correct reason for a lot of stops in a genuinely compact area. Flagged as a pattern worth watching in real (sparser) cities, not fixed, since forcing a different reason to appear when compact-route is simply the truest one would mean explaining a stop dishonestly.

### Boring discoveries
- Not observed as a problem — every itinerary that had a discovery-category candidate available picked it and explained it as a discovery (Romantic's viewpoint + theatre, Creative's gallery + arts centre, Calm's gallery, Adventure's public art, Budget's public art). The Creative itinerary in particular surfaced "Kumsal Culture & Art Center" exactly the way the sprint's own worked example asked for.

### Unrealistic costs
- The `$`-corruption bug above was the one unrealistic-looking output (a "$" budget day and a "$" splurge day reading identically). Fixed. No other cost realism issue found — the Turkey/TL path wasn't exercised by this fixture (its `center` carries no `.label`), which is an honest fixture limitation, not a code defect; covered directly by a dedicated unit test instead (`cost estimate shows a concrete TL range for a Turkey destination`).

### Missing opening hours
- None — every stop in all five itineraries shows one of the four explicit states, and Romantic's stop 3 (`restaurant_capital_4`, picked via a strong cuisine match) genuinely shows "🟡 Today's hours could not be verified." This is worth naming as a soft limitation: the romantic cuisine-match bonus can outweigh an unverified-hours stop for a special-occasion day, which is a real, observed trade-off — but changing that weighting based on this single instance would be the same kind of one-fixture overfit called out above, so it's documented, not adjusted.
